# 디지몬 RE:서바이버 v.0.18.2 (2단계: 명령 점검)

v0.18.1 기준 패치입니다. **게임 동작, 수치, 저장 형식은 바뀌지 않았습니다.** 파티와 성장 상태를 바꾸는 모든 명령을 한 틀로 점검하고, 초기화가 일어났을 때 원인을 추적할 수 있는 기록을 남기는 패치입니다.

## 적용 (파일 3개)

| 파일 | 처리 |
|---|---|
| `index.html` | 덮어쓰기 |
| `patch.js` | 덮어쓰기 |
| `sprite_data.js` | 1단계에서 올린 것과 같은 파일입니다 (변경 없음, 그대로 두어도 됩니다) |

나머지(`assets`, `retro_ui.js`, CSS)는 그대로 둡니다. 시작 화면에 `v.0.18.2 · 2단계 명령 점검`이 보이는지 확인하세요. 이전 버전이 보이면 강력 새로고침(Ctrl+Shift+R)을 하세요.

## 조사로 확인한 것

- **영입 경로는 이미 하나로 모여 있었습니다.** 지금 살아 있는 영입은 (1) 디지에그 모달 2곳(빈 자리 영입, 교체), (2) 상점 디지에그, (3) 체험장 동료 추가이고, 모두 `v181Recruit`를 거칩니다. 옛 `party[i]=` 대입 코드(175, 391, 571/574, 1105, 2997/3005, 3910/3919, 9603행 부근)는 뒤 계층이 통째로 대체해서 실행되지 않습니다. 정리(삭제)는 9단계에서 합니다.
- 판매·조그레스·낙오 제거는 이미 "대상이 파티에 있는지" 검사합니다(`indexOf` 결과가 -1이면 중단).
- 영입 때 호출되는 `ensureStarterLoadout`은 없는 항목만 추가하고 기존 멤버를 건드리지 않습니다.
- **초기화 버그의 원인은 이번에도 확정하지 못했습니다.** 코드와 자동 시나리오(아래)에서는 재현되지 않았습니다. 대신 재현되는 순간 원인을 알 수 있도록 기록 장치를 넣었습니다.

## 변경 내용

1. **명령 점검(`drCommand`).** 영입, 교체, 판매, 조그레스, 진화, 수동 퇴화, 낙오 제거, 유물 장착/해제, 기적 부활이 모두 같은 틀을 지납니다. 명령은 "변경해도 되는 개체"를 선언하고, 선언하지 않은 멤버의 성장 값이 바뀌면 **감사 기록**을 남깁니다. 되돌리지는 않고 기록만 합니다(영입은 기존대로 `v181Protect`가 복구합니다).
2. **EP 감소 감시.** 진화·퇴화·조그레스와 무관하게 EP가 줄어들면(예: 영입된 멤버의 `v070InitPartnerProgress`처럼 0으로 초기화) 호출 위치(스택)와 직전 사건과 함께 기록합니다.
3. **성장 점수 감시.** 투자, 속성 포인트, 특화 횟수의 합이 프레임 사이에 줄어들면 기록합니다. 기존 보호 장치(`v181Guard`)의 복구 기록에도 직전 사건 맥락이 붙습니다.
4. **직전 사건 기록.** 최근 80건의 명령과 모달(보상창, 상점, 디지에그) 열림·닫힘·제목을 링 버퍼에 보관합니다. 서버 전송은 없습니다.
5. **런 기록 연동.** "나의 런 기록"의 JSON에 `변경 감사` 항목이 함께 저장됩니다.

## 초기화가 보이면 이렇게 알려 주세요

브라우저에서 **F12 → Console**을 열고 아래를 입력한 결과를 복사해 주세요.

- `digimonPartyDiagnostics()` : 보호 장치와 감시가 잡은 항목 (원인 함수 위치와 직전 사건 포함)
- `digimonCommandLog()` : 최근 명령과 모달 기록

정상 플레이에서는 두 값 모두 감사/경보 항목이 비어 있어야 합니다. 비어 있지 않다면 그 자체가 단서입니다.

## 확인한 범위 (Chromium, 자동)

- g 버전과 같은 시나리오 15개가 **결과까지 동일**합니다: 빈 자리 영입, 진화 계통이 겹치는 영입(진화체의 EP·투자 유지), 가득 찬 파티 교체, 번호 재사용 없음, 오래된 교체·판매·조그레스 요청 거절, 진화 시 번호 유지, 조그레스, 기적 부활(진화체·투자·체력 50%·새 번호).
- 무작위 영입·판매·진화·오래된 요청 300단계: 파티가 1~3명을 벗어나지 않고, 번호가 겹치지 않고, 선언된 대상 외 멤버의 성장이 바뀌지 않고, 차단 기록이 0건이며, g와 단계별 결과가 같습니다.
- 새 기능: 선언되지 않은 변경은 감사로 기록, 선언된 대상은 기록 없음, 진화 직전 EP 소모는 경보 없음, EP 단독 초기화는 호출 위치와 함께 경보, 투자 초기화는 경보와 복구, 공개 함수 동작.
- 일반 플레이 85초(이동, 스킬, 보상 선택): 페이지 오류 0, 감사 0, 경보 0, 보호 장치 개입 0.
- 확인하지 않은 것: 실제 Edge, 모바일, 장시간 플레이, 상점 구매 화면의 실제 클릭, `assets`가 있는 환경에서의 그림. 이 환경에는 `assets`가 없습니다.

## 알려진 한계

- 감사와 경보는 **기록만** 합니다. 원인을 막는 수정은 원인이 확인된 뒤에 하겠습니다.
- 경보에는 드물게 오탐이 있을 수 있습니다(예: 진화와 시간차가 150ms를 넘는 정상적 EP 감소). 경보 하나가 곧 버그를 뜻하지는 않습니다. 직전 사건 기록으로 구분합니다.
